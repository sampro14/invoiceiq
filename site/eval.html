InvoiceIQ

Measured accuracy

The same documents go through one prompt to one model, and through the full agent. Both are scored by code against a frozen, hash-locked set.

Every change to main

A 25-document smoke set runs on each pull request. A change is blocked if field F1 drops more than 2 points, fully correct documents drop more than 3 points, or p95 latency rises more than 25%.

How to read this

  • Only fields a dataset has ground truth for are scored. SROIE labels four fields and CORD labels no vendor or date.
  • FATURA invoices are generated with random due dates and totals that do not add up, so the agent is right to send many of them to review. They measure reading, not the false-flag rate, which comes from the synthetic GST invoices.
  • Addresses and line descriptions count as correct at 90% string similarity. Everything else must match exactly after normalising dates, amounts, case and spacing.
  • Documents the models could not process count as wrong, not as missing.

Data: CORD v2 (NAVER Clova, CC-BY-4.0), SROIE via the jsdnrs mirror (CC-BY-4.0), FATURA2 (CC-BY-4.0), and invoices generated for this project.
